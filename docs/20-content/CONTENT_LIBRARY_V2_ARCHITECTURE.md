# Content Library V2 Architecture

Status: **FOUNDATION ACTIVE — no bulk lesson expansion yet**  
Parent issue: #103  
First implementation slice: #104  
Next slices: #105 catalog/taxonomy, #106 Content Studio

## Goal

Scale the existing drawing curriculum from the accepted 24-lesson foundation toward a deep age-appropriate library without turning the app into a hard-coded content dump or weakening offline-first behavior.

The Lesson Engine remains the execution authority. Content Library V2 adds scalable discovery, validation and authoring layers around it.

## 1. Layered architecture

```text
Child profile + local adaptive state
        ↓
Lightweight Lesson Catalog Index V2
        ↓
Home / Search / Categories / Journeys / Collections
        ↓
Selected LessonIdentity
        ↓
LessonPackageSource
        ↓
Full validated lesson package loaded on demand
        ↓
Existing Lesson Engine / Coloring / Drawing / Help / persistence
```

The full teaching package must not be required merely to render every discovery card when the catalog reaches hundreds of lessons.

## 2. Lesson package remains the teaching truth

A lesson package continues to own:
- lesson identity + revision;
- age bands;
- difficulty and estimated duration;
- category, skill, journey and prerequisite metadata;
- supported teaching modes;
- teacher stroke geometry;
- child-turn rules;
- Help ladder;
- trace geometry;
- text/localization references;
- thumbnail/preview references;
- optional coloring steps and prepared regions.

Runtime code must never branch on individual lesson IDs.

## 3. Catalog Index V2

The scalable index is metadata-only. Proposed entry fields:

```text
lessonId
revision
status
minimumContentApi
title/summary lookup metadata
ageBands
difficulty
estimatedMinutes
categoryIds
skillIds
journeyIds
prerequisiteLessonIds
tags
supportedModes
capabilitySummary
thumbnailRef
packageRef
contentFamilyId? 
```

The index must not contain teacher stroke payloads, coloring geometry or child state.

Full package loading happens only for:
- selected lesson preview where deeper detail is needed;
- lesson execution;
- validation/content tooling;
- focused prefetch if later proven necessary.

## 4. Taxonomy layers

### Age bands
Keep the accepted product bands:
- 4–5 Little Artist;
- 6–7 Creative Explorer;
- 8–9 Growing Artist;
- 10–12 Young Artist.

Age controls eligibility/presentation, not a permanent ability label.

### Categories
Categories answer: **What do I want to draw?**

Target primary taxonomy:
- Drawing Basics;
- Animals;
- Nature;
- Vehicles & Machines;
- People & Characters;
- Food & Everyday Things;
- Fantasy & Magic;
- Space & Science;
- Places & Buildings;
- Stories & Scenes;
- Patterns & Decoration;
- Comics & Expression;
- Design & Invent;
- Culture & Celebrations.

Subcategories may be editorial taxonomy records rather than new engine concepts.

### Skills
Skills answer: **What artistic idea does this practice?**

Initial skill families:
- line control;
- curves;
- basic shapes;
- shape construction;
- placement;
- symmetry;
- proportion;
- overlap/depth;
- texture/pattern;
- facial expression;
- pose/gesture;
- simple perspective;
- composition;
- visual storytelling.

### Journeys
Journeys answer: **What could I learn next?**

Journeys are optional authored sequences over normal lessons, using prerequisites where appropriate. They never block broad creative browsing.

### Collections
Collections answer: **What sounds fun right now?**

Collections are editorial groupings such as Under the Sea, Space Mission or Things That Fly. They do not alter lesson identity, completion truth or prerequisites.

### Content families
A content family groups related subject experiences across age/depth while preserving distinct lesson IDs.

Example:
```text
family.cat
  happy-cat          primary 4–5
  sitting-cat        primary 6–7
  cat-by-window      primary 8–9
  cat-in-motion      primary 10–12
```

Content families are an authoring/discovery concept, not a runtime special case.

## 5. Capability summary

Catalog cards and lesson preview must derive available actions from validated content capability truth.

Proposed summary:
```text
teachingModes: [DRAW_WITH_ME, ...]
helpAvailable: boolean
traceReady: boolean
coloring: NONE | FREEHAND | PREPARED | GUIDED_PREPARED
voiceAudio: NOT_SUPPORTED | READY
```

The summary is generated by validation/build tooling. It must not be manually duplicated from lesson data because duplicated declarations can drift.

## 6. Content scale targets

Scale is staged, not quota-driven:
- current foundation: 24;
- V2 foundation target: ~80 high-quality lessons;
- rich library: ~150;
- extensive library: ~240;
- architecture should remain comfortable at 500 metadata entries.

No phase advances because of lesson count alone. Coverage and quality reports decide readiness.

## 7. Content Health Report

For every release-catalog build, generate machine-readable + human-readable evidence for:
- total released lessons;
- lessons by age band;
- lessons by primary/secondary category;
- lessons by skill;
- difficulty distribution by age band;
- estimated-time distribution;
- supported-mode coverage;
- Help coverage;
- Trace readiness;
- coloring type coverage;
- journey sizes and prerequisite graph health;
- content-family coverage;
- missing taxonomy references;
- duplicate IDs/revisions;
- prerequisite cycles;
- missing assets/strings/references;
- capability-completeness failures;
- suspicious asset-size outliers;
- visual contact sheet of lesson thumbnails/previews.

Coverage gaps are reported, not hidden by recommendation logic.

## 8. Authoring platform boundary

Content Studio is internal tooling. The child app does not depend on it.

Content Studio may help authors:
- draw/import teacher paths;
- group strokes into steps;
- assign objective skills;
- author mode support;
- author Help levels and trace guides;
- author coloring regions;
- edit text/narration keys;
- preview all supported modes;
- validate package capability status;
- generate thumbnail/preview derivatives;
- export a normal lesson package.

The exported package must still pass the same production validator as hand-authored content.

AI assistance may propose content during authoring, but AI output has no privileged path into release content.

## 9. Storage strategy

Near-term:
- keep a strong bundled offline library;
- favor vector/JSON teaching assets;
- no child-facing network dependency.

Later, only if asset volume justifies it:
```text
CompositeLessonSource
  ├── BundledLessonSource
  └── InstalledContentPackSource
```

Downloaded packs would require an adult-controlled acquisition flow and remain fully offline after installation. This is not part of #104.

## 10. Recommendation compatibility

The accepted recommendation system remains bounded/local/explainable.

Library growth should improve recommendation quality through better metadata, not by introducing opaque scoring.

At scale the policy may add deterministic diversity such as:
- avoid repeating the same category too often;
- occasionally surface an underexposed skill;
- rotate between favorite interests and discovery;
- preserve resume precedence;
- preserve prerequisites for journey ordering;
- never infer permanent ability.

## 11. Performance requirement

Before 80+ lessons ship, Home/discovery must no longer require loading every full runtime package merely to create metadata cards.

Catalog Index V2 should be benchmarked at synthetic catalog sizes:
- 100 entries;
- 250 entries;
- 500 entries.

Correctness and deterministic filtering/ranking matter more than artificial microbenchmarks.

## 12. Delivery order

1. #104 Capability-Completeness Gate.
2. #105 Catalog Index & Taxonomy Foundation.
3. #106 Content Studio & Authoring Workflow.
4. pilot a small content family across all four age bands.
5. validate real child/product behavior.
6. only then expand toward ~80 lessons.

## 13. Non-goals

Content Library V2 does not:
- replace Drawing/Lesson/Coloring engines;
- introduce child-facing generative AI;
- add grades/ranks/mastery labels;
- add account/cloud requirements;
- make every lesson support every mode;
- fake a mode by reusing unrelated content;
- bulk-generate hundreds of lessons before the gates exist.
